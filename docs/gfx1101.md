# RX 7800 XT: Qwen3.8-27B IQ3_XXS on Linux

This fork's initial tuning target is one RX 7800 XT (RDNA 3, gfx1101, 16 GiB) running `unsloth/Qwen3.8-27B-GGUF/Qwen3.8-27B-UD-IQ3_XXS.gguf`. The model repository reports GGUF architecture `qwen35`; this is supported by the existing model loader. The file is 10,934,860,704 bytes (10.18 GiB). It is an Unsloth dynamic quantization: not every tensor necessarily uses IQ3_XXS.

These are build and measurement profiles, not a measured speedup. No GPU kernel changes or numerical approximations are enabled. Benchmark both backends on the actual card before choosing one.

## Build

Install CMake, Ninja, a C/C++ compiler and OpenSSL development files. HIP additionally needs a ROCm installation with gfx1101 device libraries, hipBLAS and rocBLAS. Vulkan needs Vulkan development files, a working Vulkan driver and glslc. See [build instructions](build.md) for platform dependencies.

Run from the repository root. For HIP, with `hipconfig` on PATH:

```bash
HIPCXX="$(hipconfig -l)/clang" HIP_PATH="$(hipconfig -R)" \
    cmake --preset gfx1101-hip-release
cmake --build build-gfx1101-hip-release --target llama-server llama-cli llama-bench --parallel 4
```

The HIP profile compiles device code for gfx1101 only. This reduces the architecture scope of the build; it does not by itself establish faster inference. Do not set `HSA_OVERRIDE_GFX_VERSION` by default. Vulkan selects the GPU at runtime rather than using a gfx1101 compiler target:

```bash
cmake --preset gfx1101-vulkan-release
cmake --build build-gfx1101-vulkan-release --target llama-server llama-cli llama-bench --parallel 4
```

## Compare

Download the exact GGUF linked above separately. Use the same file, drivers, power settings and otherwise idle GPU for both runs:

```bash
bash scripts/bench-gfx1101.sh hip /path/to/Qwen3.8-27B-UD-IQ3_XXS.gguf
bash scripts/bench-gfx1101.sh vulkan /path/to/Qwen3.8-27B-UD-IQ3_XXS.gguf
```

The script records JSON timings, stderr, binary version, source revision and tracked local changes under `results-gfx1101/`. It compares Flash Attention on/off and microbatches of 128/256/512 with batch 512, full layer offload and F16 cache. Each configuration measures prompt processing (512 tokens), generation (128 tokens), and a combined 2048-token prompt plus 128-token generation, with three repetitions. These are synthetic performance tests, not response-quality tests or a validation of a 262K context.

Check `bench.log` for GPU selection, CPU fallback, allocation failures and unsupported operations before comparing tokens/s. If an integrated GPU is also visible, use `llama-server --list-devices` from the selected build and pass `-dev DEVICE_NAME` as extra script arguments to select the RX 7800 XT explicitly. Compare prompt and generation rates separately. Keep an F16 cache baseline; optional Q8_0 cache experiments require checking backend support and response quality.

## Start a text server

Initial conservative profile, pending measurements:

```bash
build-gfx1101-hip-release/bin/llama-server \
    -m /path/to/Qwen3.8-27B-UD-IQ3_XXS.gguf \
    -ngl 99 -c 8192 -np 1 -b 512 -ub 128 \
    -fa on -ctk f16 -ctv f16 --host 127.0.0.1
```

Use the Vulkan binary instead if it wins the comparison. Preserve the GGUF's embedded chat template. This profile is text only and does not load a vision projector. Inspect startup logs to confirm offloaded layers and actual allocations; the file size alone cannot guarantee that a given context fits in VRAM.

The model configuration reports 64 layers with full attention every fourth layer, four KV heads and head dimension 256. The full-attention F16 KV payload alone is approximately 64 KiB per token, or 512 MiB at 8192 tokens. Recurrent state, alignment, compute buffers, weights and desktop usage consume additional memory. Increase context gradually after measuring peak VRAM during prompt ingestion and generation. Do not start with the advertised 262144-token context on this card.

Before accepting tuning changes, compare actual completions on fixed prompts with the baseline and check for NaNs, corrupt output or backend errors. Kernel optimization should follow measurements of IQ3_XXS matrix operations and gated delta net operations on this GPU.
